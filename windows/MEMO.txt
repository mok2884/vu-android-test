UFO202 (-24dBパッド): Lch +0.7dB / Rch +0.8dB / L/R補正 +1 (Rが1サンプル遅れる)

2026-11-24 に入れたもの (実機での確認待ち)
- 新しい配置: 2連 / 4連 (V)、INPUT 1 / INPUT 2、入力の設定の窓 (右下、VU とスコープにはかぶらない)
- キー: スペース = ラウドネス START / RESET、V = 2連/4連、R・L = RTA/LOUDNESS
- 専有モードは機器の今の周波数のまま開く (ほかの周波数は試さない)。だめなら共有にして、理由を出す
- アイコン (Android の VU METER と同じ)
- 開いている間はスクリーンセーバーとスリープを止める
- 全画面で「待ちあり」が3秒続いたら、画面を作り直して「待ちなし」に戻す (続けて3回まで)
- 「待ちあり」は赤、描くのが重くて回数が出ないときは黄色の「描くのが重い」、電池で動いていると「電池で動作中」をオレンジで出す。1回の描画の時間 (ms) も出す
- 軽くした: 文字の幅とグラデーションを作り置き、電池の確認は2秒に1回、針以外の描き直しは重いPCでは1秒30回 (2026-11-24、会社PCで54回/秒しか出なかったため)

配置の決まりごとは notes リポジトリの projects/vu-meter.md「配置の作り直し」
- 針の止まり対策 (2026-11-24): スロー動画 (120コマ/秒) で、パソコンの針が 50〜170ms 止まる場面が13秒で11回あった。
  画面の準備を待つのを最大100ms → モニターの書き換え1回分までにした。右上に「止まり ○回 (画面/音) 最大○ms」(直近1分) を出す
- 遅れの測定 (2026-11-24、SS-302 の VU と比較、UFO202 経由): 平均 約38ms (30〜47ms)。インターフェースの遅れと針の振れ方の差を含む
- 待つ時間を短くした版は「前よりパタパタする」とのこと。W キーで画面の出し方を A (前と同じ) / B (待つのは1回分まで) / C (なめらか = 書き換えに合わせる) に切り替えて見比べられるようにした。起動は A
- 見比べた結果: B は針が途中で止まって見えた。A と C はあまり違いが分からない → B をやめて、W は A (待ちなし、起動時) ⇔ C (なめらか) の切り替えにした
- 「軽くした版」あたりから針がパタつくとのこと。針以外を重いPCで1秒30回に落とす作りが原因と見て、1秒60回に戻した (ほかの軽くした部分は残す)。確認待ち
- 針の止まりの原因 (2026-11-25): 右上の表示で 画面だけ止まり、音は0。1回の描画は2msと軽いのに「待ちあり」→ グラフィック (GPU) が追いついていない。
  モノラルや LOUDNESS 表示、縮小では止まらない → ステレオのリサージュ (1024本の線をグラフィックに描かせていた) と RTA が重さの元
- 対策 (2026-11-25、VU_METER_1125.exe):
  1. リサージュは CPU で点を打った絵を作って、1枚の絵としてグラフィックに渡す。見た目は前と同じ (残像の残り方まで合わせた)
  2. 入力の設定の窓に「描く回数」: 針 240 / 120、リサージュ・RTA など 60 / 30。起動時は 240 / 60 (前と同じ)。止まるときは減らす
